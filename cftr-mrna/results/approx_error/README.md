# 근사 오차 검증 — 전체 길이 RNAfold vs RNAplfold

3단계 `metrics.py`가 전체 길이 구조를 **RNAplfold 창 150**으로 근사한 것이
타당한지 확인한 기록이다. 같은 서열에 전체 길이 RNAfold를 돌려 "정답"을 구하고,
근사값이 얼마나 어긋나는지, 후보 간 순위가 보존되는지를 측정했다.

담당: 21105 김도윤 · 2026-10

---

## 왜 했는가

후보 168개를 전부 전체 길이 RNAfold로 돌리면 약 17시간이 걸린다.
창 150 근사를 쓰면 14분이다. 이 치환이 결과를 바꾸지 않는지 아무도 확인하지 않은 채
4단계 점수화와 5단계 동역학이 그 위에 올라가 있었다.

## 계산 조건

`metrics.py`와 동일하게 맞췄다. 어긋나면 근사 오차가 아니라 설정 차이를 재게 된다.

| 항목 | 값 |
|---|---|
| 온도 | 37 °C |
| 에너지 모델 | ViennaRNA 2.7.2 기본값 |
| noLP (avoid isolated base pairs) | **사용하지 않음** |
| dangling end | 기본값 |
| RNAplfold 창 크기 W | 150 |
| RNAplfold 최대 염기쌍 거리 L | 120 |
| RNAplfold 구간 길이 u | 1 |
| 접근성 정의 | 해당 구간 위치별 unpaired 확률의 평균 |

접근성 지표 구간은 개시 코돈 A를 0으로 두고 센다.

- `acc_kozak` : −12 ~ +3
- `acc_start30` : 0 ~ +30
- `acc_mean` : 서열 전체
- 개시창 : −30 ~ +90

## 대상 후보

168개 중 9개. 순위 분포와 설계 조합(코돈 최적화 5종, 5′UTR 4종, Kozak 2종, 3′UTR 3종)을
고르게 덮도록 선정했다.

| 차수 | 순위 | 비고 |
|---|---|---|
| 1차 | 1, 2, 84, 167, 168 | 원자료 전부 보존 |
| 2차 | 32, 57, 63, 115 | 작업 환경 초기화로 원자료 유실, 요약 수치만 xlsx에 기록 |

**주의**: 1·2위가 쓰는 `match_codon_usage` 방식은 `design.py`에 난수 시드가 고정되어
있지 않아 실행마다 다른 서열이 생성된다. 여기 사용한 1·2위 서열은 저장소 원본과 다른
draw이며, 나머지 7개는 원본과 완전히 일치한다 (지표값 소수점 4자리까지 재현 확인).

## 결과

| 항목 | 값 |
|---|---|
| 속도 차이 | 117 ~ 179배 (RNAfold 329~366초 / RNAplfold 2.0~3.1초) |
| bias | 9개 전부 양수, 평균 **+0.0658**, 표준편차 0.0036 |
| MAE | 평균 0.190 |
| 위치별 상관 r | 0.699 ~ 0.778 |

RNAplfold는 창 밖 장거리 염기쌍을 세지 못해 접근성을 **일정하게 과대평가**한다.
편향의 크기가 서열 구성과 거의 무관하게 일정하므로, 후보 간 상대 비교에서는 상당 부분 상쇄된다.

### 지표별 순위 보존

| 지표 | Kendall τ | 판정 |
|---|---|---|
| `acc_mean` | +0.889 | 보존됨 |
| `acc_kozak` | +0.694 | 대체로 보존됨 |
| 개시창 (−30 ~ +90) | +0.250 | 불안정 |
| `acc_start30` | +0.083 | **보존 안 됨** |

`acc_start30`은 CDS 내부라 장거리 결합 노출이 가장 크다. 84위 후보는 전체 길이 기준
0.2799로 9개 중 가장 닫혀 있으나, 근사 기준으로는 0.4451로 가장 열린 축이 되어 순서가
완전히 뒤집힌다. 민감도 분석에서도 제거 시 순위상관 0.969로 영향이 미미했던 지표이므로,
점수식에서 제외할 것을 권고한다.

### 부수 발견

3′UTR만 다른 후보 쌍(1위/2위, 167위/168위)을 RNAplfold는 동일하게 평가하나
전체 길이 RNAfold는 구분한다 (1위 0.4227 vs 2위 0.4774). 3′ 말단이 개시부와
장거리로 결합하고 있으며, 창 150 근사는 이를 원리적으로 포착할 수 없다.
3′UTR 선택이 개시 효율에 미치는 영향을 현재 지표 체계가 측정하지 못한다는 뜻이다.

## 한계

- 168개 중 9개 표본이다. 전수 검증이 아니다.
- 2차 4개는 원자료가 남아 있지 않아 재현하려면 재계산이 필요하다.
- 전체 길이 값과 근사값은 기준이 다르므로 섞어서 순위를 매기면 안 된다.

### `pos_*.csv` 열 설명

| 열 | 의미 |
|---|---|
| `pos` | 염기 위치 (1부터) |
| `unpaired_rnafold` | 전체 길이 RNAfold가 계산한 그 자리의 열림 확률 |
| `unpaired_rnaplfold` | RNAplfold(창 150)가 계산한 같은 값 |
| `diff` | RNAplfold − RNAfold. 양수면 근사가 더 열려 있다고 본 것 |

### 오차 지표의 뜻

- **MAE** — `diff`의 절댓값 평균. 위치별 판단이 얼마나 어긋나는지.
- **bias** — `diff`의 평균. 부호가 남으므로 어긋남의 **방향**을 보여준다.
- **Pearson r** — 전 위치에 대한 두 방법 값의 상관.
- **Kendall τ** — 염기가 아니라 **후보끼리**의 순서 일치도. +1이면 완전 일치, 0이면 무관계.

## 재현 방법

```bash
pip install ViennaRNA          # 2.7.2에서 검증
python code/approx_error.py    # 후보 1개당 약 6분
```

입력은 `cands5.json`이며, `design.py`로 후보를 재생성해 만든다.
형식은 `[{"rank":1, "id":"...", "cds_start":56, "sequence":"..."}, ...]`이고
`cds_start`는 5′UTR과 Kozak 길이의 합이다.

ViennaRNA 웹 서버로 교차 검증할 때는 위 계산 조건과 맞춰야 한다.
Fold Algorithm을 "minimum free energy (MFE) and partition function"으로 두고,
"avoid isolated base pairs"를 비롯한 모델 수정 옵션은 모두 끈다.
1위 MFE −1481.2, 168위 −1274.3이 나오면 일치한다.
